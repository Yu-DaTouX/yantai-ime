# 全拼整句方案实测（设置页「整句」各开关）

评测集：`quanpin_sentence_eval_300.tsv`，320 条自拟句子（聊天/工作/新闻/生活各 80 条，4–20 字，无声调全拼连写）。
工具：`engine/tests/src/eval_quanpin_sentence.cpp`，一个模式一个进程，同一台机器连跑，数据目录是
`%LOCALAPPDATA%\metasequoiaime` 的副本（`E:\yantai-wt\.bench-data`），模型另下载进副本。

口径：

- **首选率**：候选列表第 0 行等于期望文本的比例。**前 3 率**：期望文本出现在候选列表前 3 行（整页前 3 项，
  不只看整句行）里。单来源模式下前 3 率恒等于首选率，因为整句只占一行，第 2/3 行是前缀词库候选
  （实测 320 条里没有一条期望句落在第 2/3 行）；组合模式出现两个来源时才拉开差距
  （`trigram+neural_desktop` 首选 92.81% / 前 3 94.06%），说明这一列读的是整页前 3 项。
- **每键均值/P95**：只算 `handle_character` 的同步耗时，预热轮不计；标「3 轮」的是三轮各自聚合后取中位数，
  标「1 轮」的只跑了一轮（机器上同时有别的编译任务，单轮值只作量级参考）。神经重排的等待时间不含在内。
- **ready_ms**：最后一键之后，后台重排结果到齐（神经行出现、或候选列表连续 400 ms 不再变化）的时间中位数；
  轮询口径含重查开销，粗于按键耗时。它是「整句行什么时候才出现」的用户可见延迟。
- **内存**：该模式进程的工作集峰值（`GetProcessMemoryInfo` 的 PeakWorkingSetSize）。.gram 是 mmap，
  只有真正查到的页进内存，所以峰值远小于文件体积；单来源模式各自独占一个进程，数字可比。
- 数据目录、sc.lm 与四个 octagram 模型都放在副本里，sc.lm 的 SHA-256 与产品锁定值一致
  （`3588b394…218387`）；octagram 模型由引擎的 `GramDb::open` 校验通过后才进表。

### 分项观察

- **Unigram 整句单独用明显不够**（59.4%），它和 sc.lm 无关，只是 Google 解码器那条兜底；但它和神经·效果优先
  叠加后把首选率从 75.0% 拉到 90.0%，说明两条来源互补：Unigram 覆盖长句里的常用搭配，神经模型补它挑错的地方。
- **Trigram（sc.lm）是最划算的单来源**：86.3% 首选，每键 0.69 ms，峰值 56 MB；再叠加神经·效果优先到 92.8%。
- **神经网络·效果优先单独用反而只有 75.0%**：它不是自己造句，只在词格的 12 条 n-best 里挑；开着它时词格
  不显示自己的首选行，于是「挑错」直接暴露成首选错误，而且有些输入里排在第 0 位的还是前缀词库候选
  （实测 `wobalajinaxialourengle` 的首行是「我爸来」，整句行在第 2 位之后）。它适合跟 Trigram/Unigram 一起开，
  不适合单独开。另外它要 312 ms 才出整句行，明显晚于打字节奏。
- **神经网络·速度优先单独用最稳**：88.4% 首选，ready 85.9 ms，峰值 64 MB。叠加 Trigram 后 90.3%（ready 76 ms）。
- **octagram**：万象（390 MB）87.5% 是四个里最好的，和单独 Trigram（86.25%）基本同档，但每键 1.49 ms、
  峰值 268 MB；八股文 197 MB 79.7%、紧凑 39 MB 80.6%（体积缩五倍、准确率只差 1 个点、每键快 0.36 ms）；
  白霜 7 MB 74.4%。四个模型都是「解码期加搭配分」，都只能改善单来源词格，不能替代 sc.lm 的句法约束。
- **内存与体积不成正比**：.gram 走 mmap，只把查到的页读进来——万象 390 MB 的文件峰值 268 MB，白霜 7 MB 峰值 62 MB
  （其中约 25 MB 是词库与引擎本身）。磁盘占用按文件大小算，运行占用按上表峰值算。
- **上文词库重排**：它只重排「整读音的词库候选」（单字/词组），长句输入没有整读音词条可排，所以在这 320 条句子上
  一条都没改动首选（首选率与全关一致 0%，耗时 +0.07 ms 是开关本身的开销）。它要配上文才有意义，见下节探针。

## 上文词库重排的选择集探针

`quanpin_context_rerank_cases.tsv`：20 条「上文 + 单双音节词」用例（如「冬天会下大」+ `xue` → 雪），
第 4 列是上文。同一份输入跑一次不带 `context`（基线）与一次带 `context`（上文重排）对照。

**这一节没有数字**：跑探针的两条命令排在 octagram 组合之后，本次限时内没轮到。工具已经支持
（`--mode off` / `--mode context` 配这份文件），复跑命令：

```
eval_quanpin_sentence engine\tests\data\quanpin_context_rerank_cases.tsv --mode off     --rounds 3
eval_quanpin_sentence engine\tests\data\quanpin_context_rerank_cases.tsv --mode context --rounds 3
```

## 推荐配置

**日常首选：Trigram（下载 sc.lm）+ 神经网络·速度优先**——首选 90.3%、前 3 91.9%、每键 0.73 ms、
整句行 76 ms 内出现、峰值 63 MB，模型只要 34.7 MB + 4.3 MB。
**追求准确率**：再把神经网络·效果优先打开（Trigram + 效果优先 92.8%，多 25 MB 模型、整句行晚到约 246 ms）。
**不推荐单开神经网络·效果优先**；**octagram 只在没有 sc.lm 时才考虑**，要开就选万象（+1.3 个点、多 268 MB 内存）
或紧凑八股文（-5.6 个点、每键 +1 ms、只多 94 MB 内存）；390 MB 的万象与实际收益不成比例。
