### 1.2 旧出厂词库的来源与流程

已核对产品锁指定提交的源码，而非只看上游最新 README：

1. `dictionary/source/BaseDict.txt` 来自 CustomPinyinDictionary，版本标为 `2023-09-28(No.82)`，原始 **1,415,159 条**【来源：该提交 `dictionary/README.md`；与输入文件去重计数吻合】。
2. `BaseDictIce` 来自雾凇；`SingleCharsAllV1` 合并雾凇单字并用 pinyin-data 校正；`SingleCharWhitelist` 过滤收录单字。
3. 两个 `BaseDictAllV1Part*.txt` 是旧百万词库与雾凇合并、去重后的直接建库输入。
4. `build_all.py:96–127` 串起建表→插入→建索引；后续追加五笔、快捷短语、日语等。`build_profile.py` 冻结为 DELETE journal，产出 manifest 与 SHA256SUMS；发布后 Windows 按产品锁取产物。
5. `engine/contracts/dictionary/format.json` 规定按**音节数**分表：1–7 为 `tbl_N_首字母`，≥8 为 `tbl_others_首字母`；列为 `key/jp/value/weight`。`key` 用单引号分音节，`jp` 为音节首字母串，不能建 `tbl_8_*`【来源】。

旧上游自己已经披露授权缺口：CustomPinyinDictionary 未声明许可、SingleCharWhitelist 来源待确认、日语 jp_sela 未声明许可；旧混合库不能因为应用是 GPL 就视作全部已获再分发授权【来源：[固定提交 NOTICE](https://github.com/metasequoiaime/MSIME-Engine/blob/d0dc0c2b594b5540b5de99ad12085c786410626e/dictionary/NOTICE.md)】。

### 1.4 抽样短板：别把历史词、口语或多读音一概当垃圾

下列均为快照直接查询【实测：`baseline-stats.json`、`comparison.json`】：

- **不成词的高频碎片**：`的吧 de'ba=9999`、`的了 de'le=1111`、`吧啊 ba'a=5555`、`你你 ni'ni=4444`、`时间和 shi'jian'he=100`、`鱼的 yu'de=72540`。白霜核心删除其中这些行；全细胞版又把部分带回来，权重降至 `1`。语料中能出现，不代表适合做词格里的高优先级整词。
- **可定位的错读音**：`长达 zhang'da=1`、`行长 xing'zhang=1`；白霜核心没有前者的错误读法，正常 `长大 zhang'da`、`行长 hang'zhang` 仍在。不能把 `便宜 bian'yi`、`重重`、`朝阳` 的多读音直接算错——它们有合法语境。
- **旧热点不宜机械删除**：`人人网=100`、`开心网=100`、`元芳你怎么看=100`、`博客=500448` 仍有历史/日常用途，宜降权或放扩展层；不能声称它们「不存在」。白霜中「元芳你怎么看」降为换算后 `15`，博客为 `24745`。
- **新词缺口**：现库没有整词「新质生产力」「具身智能」。推荐白霜组合补到了前者，但仍缺后者；不能把 repo 最近有更新等同于新词全面覆盖。
- **个人历史会影响干净度**：现库 `wo` 的「握」权重 **29,569,761**，紧贴「我」**29,570,261**【实测】，不能据此断定旧出厂库如此。更新出厂词库与保留用户偏好是两件事。

## 2. 白霜优先：许可、词频、读音、分包

实验固定白霜提交 **`af267b67162ca4098c7f8d48b77bbfc8222a10e5`**，不是浮动 master；下载 SHA256 清单保留在实验目录。

### 2.1 为什么适合作为首选

白霜是雾凇的派生词库，先删不健康/低质量词、手工调频，再重新统计字词频。README 声称使用 **745,396,750 字**高质量语料【来源，未下载语料复核】；`others/program/README.md:19–130` 和 `reduce_freq_base_to_zhifreq.py` 展示了 MNBVC 中知乎回答正文→Jieba 分词→频次合并→升降频表→多音字频次分配的流程。它的优势不是单纯「比雾凇条目多」，而是愿意做减法和维护频率。

许可结论：**白霜作者发布的 GPL-3.0 内容可以修改并随 GPL-3.0 项目分发**；保留白霜、雾凇署名及许可，明确转换/筛选修改，公开固定版本源文件、转换脚本和构建配方。作者 issue #290 的明确同意是补强证据，不是给所有第三方来源的无限担保。`cn_dicts/base` 的头部仍列华宇野风、THUOCL、腾讯词向量等来源；`cn_dicts_cell` 也没有每包完整的原始授权链。**「白霜 GPL 可用」与「来源链逐项审计已完成」不能混为一谈**。本次未完成逐原作者授权调查，公开发行前应补 provenance 清单；目录名带 cell 本身也不能证明它就是搜狗 SCEL 抓取物。

### 2.3 多音字：沿用词级注音，不重新逐字笛卡尔展开

白霜 base/ext 有人工和 pypinyin 修订；腾讯包头解释了 Rime 自动注音与多音字处理历史，但**本次固定提交的白霜 tencent 数据已全部显式注音**【实测】。不能照搬雾凇当前腾讯包仍无注音的结论。

人工固定 **30 个**多音/易误读词探针，包括重庆、银行、音乐、长大、长安、角色、模样、薄荷、秘鲁、贾平凹、六安、荨麻疹等；现库与各白霜变体都包含预期读音，均 **30/30**【实测：`comparison.json.polyphonic`】。它只证明这些样本的**正确读音存在**，不证明其他错误读音不存在，更不是全库正确率。

转换器使用上游词级 code；空格转单引号，保留 ü→v，去调并校验字数/音节数，不用单字最常见读音自动重注所有词。特别跳过 corrections，例如 `角色 jiao se`、`模样 mo yang`、`说服 shui fu` 原本是纠错入口，不能混成正常读音。热点包中的「我嘞个豆」记为 `wo le ge dou`，本次人工探针用 `wo lei ge dou`，所以只算文字存在、不算指定读音命中；这种口语分歧单列，不伪装成确定的全库错误率。

## 5. 转换与词频尺度：本次已经做了什么

脚本：`E:\yantai-wt\dict-probe\convert_frost.py`，仅 Python 标准库，拒绝覆盖现存输出，拒绝输出到实验目录外。

```bash
# 纯核心：去掉 --cell-pack；腾讯版：--tencent；近默认版：--cells --gb18030
```

转换规则：

1. 只读 `...` 之后的明确注音行；本实验全拼表只接收汉字/〇，不把英文、符号和 Rime Lua 当拼音词导入。无读音行拒绝，不偷偷生成多音组合。
2. 用契约一致的 184 张分表；按音节生成表名和 jp；索引 `idx_key_*`、`idx_jp_*`；保留空 `quick_parases` 与 `latin_words` 的现有查询入口，不建五笔/日语。
3. `(key,value)` 去重取最高上游频次，不把相同词被多包收录的频次相加；相同文本不同正确读音可并存。
4. 权重使用 `max(1,min(100000000,白霜频次×5))`。**5 是首轮尺度估算参数，不是声称最优拟合**；以旧库最高约 7,694 万、引擎 managed ceiling 一亿为护栏，保留白霜内部比例与排序，换算后最高 **76,892,375**【实测】。零频词降为兜底 1，不把 tencent 零频升到现库常见的 100/9999。
5. 这个统一倍率没有消除白霜字/词比例与本引擎评分的差异；`word_lattice.cpp:63–100` 使用 log 权重与读音先验，所以排序不只是 SQL 单键比较。正式发布可在独立开发集搜索单字/多字比例和新词层上限，须另留测试集，避免调到这套 320 句上。
6. 输出 DELETE journal、integrity_check、源文件哈希、逐包新增/重复/拒收样本、转换清单；不把用户库复制进成品。

验证：`test_conversion.py` 的 **5 个测试全部通过**【实测】，覆盖契约、去调/ü、Unicode、拒收逻辑和所有实验库的逐行分表/jp/权重一致性。推荐库独立重建后 `cmp` **字节完全相同**【实测】。这是格式/可重建验证，不等于人工审完所有注音。

后续合并层建议：**白霜原始层→已核准专业/热点小包→本项目纠音/禁用清单→人工新词 overlay→用户日志回放**。每个 overlay 带来源、许可、提交日期、词级读音及可选失效/复审日期。新词从同读音现有分布中低位插入，明确需要改首选时才显式提权，不用「所有新词统一极高权重」。这是【方案，未实测全量人工新词包】。

**推荐落点【方案】**：转换规则/测试放进本仓 `scripts/dictionary_build/frost.py`，由现有 `build-dictionary.py` 选择 `--pinyin-source frost`，不要新建另一套安装器；外部文本原料按现有架构放 `msime-dictionary` 的 `sources/pinyin/frost/`（或固定 commit＋文件 SHA256 的下载缓存），自建词/纠音放 custom。此路径只是建议，**本次没有修改这两个仓库，也未读取未授权的其他本地词库目录**。

1. 更新输入锁与清单：白霜 commit、各源文件摘要、包列表、倍率、转换器摘要、许可证和修改记录都进入构建身份；不要继续让 stale marker 只看外部数据仓 commit、却不知道分包参数变了。

2. **最低成本离线做法【方案】**：两端导出词条增删记录为版本化 UTF-8 文件，用 USB/用户自行拷贝导入；仅处理本分支支持的 pinyin/quick/english，忽略 Android 五笔类别，规范拼音为单引号分隔。明示「合并」和「整份替换」，保留删除记录及备份。若已有两端可识别导入格式，应先做 round-trip；本次没有设备实测，不能承诺直接导入某文件即可成功。
3. **若要跨端复制完整习惯**，Windows 已有 `stream_dictionary_state/stage_dictionary_state`（`engine/docs/dictionary-state.md`）：一致性导出、在独占新目录准备、会话空闲后原子切代。可先做用户确认的全量备份/恢复；**它本身不是实时双向冲突合并协议**。Android 还有 [learning-sync v1 设计/分期文档](https://github.com/metasequoiaime/msime/blob/21aacdded83643576e4a0318803e34b6e7d258bc/docs/learning-sync.md)，涉及 E2EE、时间戳、删除与固定位置；不能因文档存在就认定本 Windows 已兼容或端到端已验证。
4. 基础词库内容标识、权重尺度不同应警告；最好 PC/手机使用同一份白霜来源与分包。不要同步整个 msime.db/WAL、输入记录、账号凭据或模型。保持本地离线输入为默认，同步明确自愿；WebDAV 为可选能力而非换词库的前置条件。
